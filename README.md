# 📝 To-Do List REST API

A simple RESTful API built with **Node.js** and **Express.js** that performs full CRUD operations (Create, Read, Update, Delete) on a list of tasks.

> **Note:** Tasks are currently stored in memory, so data resets when the server restarts. MongoDB integration is planned for a later stage.

## 📖 About the Project

This project is the backend of a To-Do List application. It exposes REST endpoints that let a client create tasks, view them, update their details or completion status, and delete them. It follows RESTful design principles: resource-based URLs, correct HTTP methods, meaningful status codes and JSON for all requests and responses.

## ✨ Features

- Create, view, update and delete tasks
- Server-side input validation (a task title is required)
- Unique, auto-generated task IDs
- Partial updates (send only the fields you want to change)
- Proper HTTP status codes: `200`, `201`, `400`, `404`
- JSON requests and responses

## 🚀 Getting Started

### Prerequisites

- [Node.js](https://nodejs.org) v18 or later
- npm (comes with Node.js)

Check your installation:

```bash
node -v
npm -v
```

### Installation

1. **Clone the repository**

   ```bash
   git clone <your-repository-url>
   ```

2. **Go to the backend folder**

   ```bash
   cd assig7/backend
   ```

3. **Install dependencies**

   ```bash
   npm install
   ```

   If `express` is not installed, run:

   ```bash
   npm install express
   ```

### Running the Server

```bash
node server.js
```

You should see:

```
Server is running on port 5000
```

Open `http://localhost:5000` in your browser. The response should be:

```
To-Do List API is running
```

Press `Ctrl + C` to stop the server.

## 🔗 API Endpoints

**Base URL:** `http://localhost:5000`

| Method | Endpoint | Description | Success | Errors |
|---|---|---|---|---|
| GET | `/` | Health check | 200 | None |
| GET | `/tasks` | Get all tasks | 200 | None |
| GET | `/tasks/:id` | Get a single task | 200 | 404 |
| POST | `/tasks` | Create a new task | 201 | 400 |
| PUT | `/tasks/:id` | Update an existing task | 200 | 400, 404 |
| DELETE | `/tasks/:id` | Delete a task | 200 | 404 |

### Task Object

| Field | Type | Description |
|---|---|---|
| `id` | Number | Unique ID generated by the server |
| `title` | String | Task name (required) |
| `description` | String | Extra details (optional, defaults to `""`) |
| `completed` | Boolean | Task status (defaults to `false`) |

## 📬 Request and Response Examples

### Create a task: `POST /tasks`

**Request body**

```json
{
  "title": "Learn Express",
  "description": "Create my first API"
}
```

**Response `201 Created`**

```json
{
  "id": 1,
  "title": "Learn Express",
  "description": "Create my first API",
  "completed": false
}
```

**Error `400 Bad Request`**

```json
{ "message": "Task title is required" }
```

### Get all tasks: `GET /tasks`

**Response `200 OK`**

```json
[
  {
    "id": 1,
    "title": "Learn Express",
    "description": "Create my first API",
    "completed": false
  }
]
```

### Get one task: `GET /tasks/1`

**Response `200 OK`**

```json
{
  "id": 1,
  "title": "Learn Express",
  "description": "Create my first API",
  "completed": false
}
```

**Error `404 Not Found`**

```json
{ "message": "Task not found" }
```

### Update a task: `PUT /tasks/1`

**Request body** (all fields are optional)

```json
{
  "title": "Learn JavaScript",
  "description": "Practice REST APIs",
  "completed": true
}
```

**Response `200 OK`**

```json
{
  "id": 1,
  "title": "Learn JavaScript",
  "description": "Practice REST APIs",
  "completed": true
}
```

**Errors**

- `404`: `{ "message": "Task not found" }`

**Response `200 OK`**

```json

```

**Error `404 Not Found`**

```json
{ "message": "Task not found" }
```

## 🔢 Task ID Generation Logic

Every task needs a unique ID so it can be fetched, updated or deleted without confusion.

```js
let nextId = 1;

const newTask = {
  id: nextId++,
  title: title.trim(),
  description: description || "",
  completed: false
};
```

**How it works**

1. `nextId` starts at `1` when the server starts.
2. When a task is created, it gets the current value of `nextId`, and then the counter increases by 1.
3. The first task gets ID 1, the second gets 2, and so on.
4. The counter only goes up, so two tasks never share an ID.
5. The client never sends an ID. Only the server decides it.

**After deletion:** IDs are never reused. If tasks 1, 2 and 3 exist and task 2 is deleted, the next new task gets ID 4. This stops an old reference from pointing to the wrong task.

**Lookup:** the ID arrives in the URL as text, so the server converts it with `Number(req.params.id)` before comparing it with each task's numeric `id`.

## 🧪 Testing the API

You can use Postman, or PowerShell commands like these (restart clears all tasks, so create a task first):

```powershell
# 1. Create a task
$new = @{ title = "Learn Express"; description = "First API" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:5000/tasks" -Method Post -ContentType "application/json" -Body $new

# 2. Get all tasks
Invoke-RestMethod -Uri "http://localhost:5000/tasks" -Method Get

# 3. Get one task
Invoke-RestMethod -Uri "http://localhost:5000/tasks/1" -Method Get

# 4. Update the task
$body = @{ title = "Learn JavaScript"; completed = $true } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:5000/tasks/1" -Method Put -ContentType "application/json" -Body $body

# 5. Delete the task
Invoke-RestMethod -Uri "http://localhost:5000/tasks/1" -Method Delete
```

> `Invoke-RestMethod` shows a red error for 404 and 400 responses. This is normal and means the API is returning the error correctly.

## ⚠️ Challenges and Limitations

- **No persistence:** data is stored in memory and is lost on every restart.
- **Single-server IDs:** the counter works for one server only and resets on restart.
- **Basic validation:** more checks (for example, invalid ID formats) can be added.
- **No authentication:** anyone can access every task.
- **CORS:** must be enabled when a frontend on another port calls this API.
